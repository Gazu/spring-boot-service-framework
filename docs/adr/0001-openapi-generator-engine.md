# ADR 0001: OpenAPI Generator As The Source-Generation Engine

- Status: Accepted
- Date: 2026-08-19

## Context

The framework currently parses OpenAPI documents and renders Java models,
server APIs, clients, JAR files, and Maven metadata through custom Gradle and
Java implementations. Maintaining a complete OpenAPI parser and Java generator
duplicates established tooling and makes advanced OpenAPI support expensive.

The framework-specific value is its artifact conventions, Spring Boot Service
Framework integration, compatibility policy, reproducibility requirements,
and publication workflow.

## Decision

OpenAPI Generator is the source-generation engine for models, Spring server
delegates, and Spring HTTP Interfaces. The engine version is pinned by the
framework build and is upgraded only through reviewed compatibility checks.

The framework provides a thin, public Gradle convention plugin with the
`smbtechOpenApi` DSL. It owns contract selection, artifact coordinates,
package conventions, generation options, metadata, compatibility policy, and
Maven publication. Framework-specific source changes are implemented through
versioned Mustache templates instead of a parallel OpenAPI parser or renderer.

Project scaffolding is a separate, one-time operation based on Spring
Initializr. It consumes the original OpenAPI document directly or extracts it
from a published server API JAR. OpenAPI DTOs remain transport models and are
not inferred as domain entities.

## Module Ownership

| Module | Responsibility |
|---|---|
| `spring-boot-service-framework-openapi-gradle-plugin` | Public DSL, Gradle task orchestration, validation and publication wiring |
| `spring-boot-service-framework-openapi-templates` | Versioned OpenAPI Generator Mustache overrides |
| `spring-boot-service-framework-project-generator` | One-time Spring Boot and hexagonal project scaffolding |
| `spring-boot-service-framework-openapi-contract-testing` | Optional executable MVC contract verification |
| `spring-boot-service-framework-starter-mock` | Optional runtime mock endpoints loaded from OpenAPI |

## Compatibility Rules

- `info.title` determines normalized artifact names.
- `info.version` determines the generated artifact version.
- Models are published once and referenced by server API and client artifacts.
- The original contract and generator metadata are embedded in published JARs.
- A generator or template upgrade that changes public generated bytecode
  requires a new contract version; released coordinates are immutable.
- Contract generation and project scaffolding remain separate workflows.

## Transition

Completed: the embedded Gradle script and custom generator module
were removed after artifact generation, compatibility checks, publication, and
project scaffolding moved to their final owners.

## Consequences

The framework stops owning general OpenAPI language support and gains the
generator's model and Spring feature coverage. Generator upgrades require
controlled output review. Framework-specific customization is intentionally
limited to conventions, policy, and small templates.
